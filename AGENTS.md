# Trigger Information

Codex, claude code, antigravity or any other agent should read this everytime before making change. 


## MOST IMPORTANT RULE

**Every change must be made and fully tested on localhost first.  
Do not change the live website unless the user explicitly says to do so.**

The localhost and live website must always remain synchronized and identical in:

- Design
- Layout
- Content
- Navigation
- Mobile view
- Desktop view
- Header
- Footer
- Functionality
- WordPress settings

Never make an unapproved direct change on the live website.

---

## 1. Change Only What Was Requested

- Modify only the exact item requested.
- Do not disturb unrelated pages, sections, styles, settings, or functionality.
- Use the smallest possible change.
- Do not redesign or replace other areas unless explicitly instructed.

---

## 2. No Hard-Coded Content

Do not hard-code names, prices, text, images, links, menu items, or other editable content.

All changeable content must be editable from the WordPress admin panel without:

- Writing code
- Redeploying the website
- Editing theme files

Placeholder content such as “Sarah Jenkins” must never be added as permanent content.

---

## 3. Kadence Parent Theme Only

- Use the Kadence parent theme as the native foundation.
- Never create or use a child theme.
- Keep the header, footer, body, menus, layouts, and responsive settings editable through WordPress and Kadence.
- Use Kadence-native features wherever possible.

---

## 4. Match the Reference Design

- Follow the attached design exactly.
- Preserve spacing, sizing, typography, colors, alignment, and responsive behavior.
- When one item needs to be compact, change only that item.
- Do not apply broad global changes for a local issue.

---

## 5. Protect Mobile, Desktop, and Navigation

Do not disturb:

- Mobile flow
- Desktop flow
- Navigation
- Menus
- Dropdowns
- Header
- Footer
- Section order
- Responsive behavior

Always test changes on mobile, tablet, laptop, and desktop.

---

## 6. Protect SEO, AU, GEO, and Coreas Rules

Do not disturb existing:

- SEO settings
- AU settings
- GEO settings
- Metadata
- Schema
- Canonical URLs
- Redirects
- Permalinks
- Internal links
- Analytics
- Indexing settings

When internal linking is requested, follow the agreed Coreas SEO framework without changing unrelated design or homepage structure.

---

## 7. Database and Environment Safety

- Do not assume localhost and live databases are already synchronized.
- Never overwrite the live database without explicit approval.
- Do not use a full database replacement for a small change.
- Prevent localhost URLs, test content, placeholder data, and development settings from reaching the live website.
- After an approved live update, confirm that localhost and live remain identical.

---

## 8. WordPress Admin Editability

The owner must be able to update the following from WordPress:

- Prices
- Content
- Images
- Links
- Menus
- Header
- Footer
- Page sections
- Product or menu information
- Repeated content

Use WordPress, Kadence, custom fields, menus, reusable blocks, or existing plugin data where appropriate.

---

## 9. Plugin and Code Safety

- Do not edit WordPress core files.
- Do not edit plugin core files.
- Do not disable plugin functionality to make a design work.
- Keep plugin compatibility as far as the native Kadence approach allows.
- Use scoped CSS and targeted code.
- Avoid global CSS, fragile selectors, and unnecessary dependencies.
- Do not expose credentials, API keys, or database information.

---

## 10. Required Workflow

For every task:

1. Identify the exact requested change.
2. Review the existing localhost implementation.
3. Make the change on localhost only.
4. Test the requested change.
5. Confirm that unrelated areas remain unchanged.
6. Test mobile, desktop, navigation, header, footer, SEO, and dynamic content.
7. Show or report the localhost result.
8. Update the live website only after the user explicitly approves or instructs it.
9. After the live update, verify that localhost and live are identical.

---

## Final Rule

**Work on localhost first, never change live without permission, keep localhost and live synchronized, change only what was requested, and keep all editable content manageable through WordPress.**
